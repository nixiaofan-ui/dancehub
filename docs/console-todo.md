## 一、上线前必做

### 1. 用户隐私保护指引：增加「剪贴板」

不做：`wx.setClipboardData` 在正式 appid 下直接 fail，报
`setClipboardData:fail api scope is not declared in the privacy agreement`，
表现为「点了复制毫无反应」（现在代码已经会弹提示 + 打日志，但功能仍不可用）。

路径：微信公众平台 → 设置 → 基本设置 → 服务内容声明 → **用户隐私保护指引**
→ 更新 → 增加信息类型 → 勾选「**剪贴板**」

用途文案（照抄即可）：

```
用于复制舞室名称，方便用户前往该舞室的官方小程序完成预约
```

改完要**重新生成协议并等待几分钟生效**；若体验版仍失败，去「版本管理 →
体验版 → 提交审核页面」里的隐私保护指引再更新一次。

### 2. 模糊定位：接口权限 + 隐私指引

不做：`wx.getFuzzyLocation` 直接 fail，定位按钮只会提示「定位失败」。

1. 小程序后台 → 开发 → 开发管理 → **接口设置** → 自助开通「获取模糊地理位置」
2. 用户隐私保护指引 → 增加信息类型 → 勾选「**位置信息**」

用途文案：

```
用于获取用户所在城市，自动展示当地舞室的课表
```

> 用模糊定位（getFuzzyLocation）而不是精确定位（getLocation）：
> 我们只需要城市粒度，精确位置属过度索取且类目多半申请不下来；
> 二者在 `app.json` 的 `requiredPrivateInfos` 里**互斥**，只能声明一个。

### 3. 上传体验版 / 提交审核

`app.json` 改了（新增 `requiredPrivateInfos`、`permission`），小程序代码必须
重新上传才会生效。微信开发者工具 → 上传 → 后台设为体验版。

## 二、云端自动抓取（方案 B）

代码已就绪（并发 + 时间预算 + 出口连通性自检），剩下三处控制台配置：

| # | 位置 | 操作 | 为什么 |
|---|---|---|---|
| 1 | 云托管 → 服务 → dancehub-server → 服务设置 → 环境变量 | 把 `SKIP_CRAWLER` 改成 `0`（或删掉），并加 `CRAWL_MODE=scheduler` | 云端才会启动抓取调度 |
| 2 | 云托管 → 服务 → 版本/扩缩容配置 | 最小副本数设为 **1** | 缩到 0 就没人跑心跳，定时触发器唤醒的实例也会在请求结束后被销毁，抓一半就没了 |
| 3 | 云托管 → 服务 → 服务设置 → 公网访问 | 打开（可选，但强烈建议） | 拿到公网域名后可直接 `GET /api/crawler/probe` 自查出网，不用翻日志 |

改完重启实例（发布一次或直接等），看日志里这一行：

```
[crawler] 出口连通性自检：可用 — generic=OK aiwugong=OK
```

- **可用** → 每 6 小时自动补抓一次，587 家约 3 分钟跑完，无需人工干预
- **不可用** → 容器出不去公网，把 `SKIP_CRAWLER` 改回 `1`、最小副本数改回 `0`，
  数据仍走「本机抓取 + `server/scripts/sync_cloud_db.sh` 推云库」

> 出网不通很可能就是当初把云端抓取关掉的原因，所以这条日志是唯一决定性证据。

## 三、可选优化

### 逆地理定位（更准）

现在「定位 → 城市」用的是**最近城市中心点**算法（离线坐标表，无需任何 key）。
在广佛、深莞这类相距不到 30km 的城市群边界上可能判错（比如佛山判成广州），
用户可在城市条上手动纠正。

要更准：去 [腾讯位置服务](https://lbs.qq.com) 申请 key，在云托管环境变量里加

```
TENCENT_MAP_KEY=你的key
```

服务端会自动改用逆地理编码，无需发新版小程序。
